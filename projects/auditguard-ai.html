Engagement brief — fictional Meridian Rail Logistics

Audit objective: Evaluate whether privileged access, segregation of duties, and production system changes are authorized and traceable. Period: October 2026 (illustrative). Risk: Unauthorized access, unapproved transactions, and unreviewed changes could compromise data integrity and operational reliability. Deliverables: risk/control matrix, test results, evidence-linked workpaper, and management-ready observations.

Audit conclusion and reviewer considerations

This small, intentionally selected synthetic sample is designed to demonstrate both exception and non-exception outcomes. It cannot establish a population exception rate, control effectiveness, or operating effectiveness for a real organization. A professional audit would verify completeness and accuracy of the source population, determine sampling methodology, corroborate flagged records, assess compensating controls, and obtain management responses before reporting.

Methodology and limitations

Control objectives: (1) privileged access should have current approval, (2) transaction request and approval should be performed by different people, and (3) production changes should have documented approval before deployment. Rules are illustrative; exceptions are indicators requiring corroboration, not confirmed control failures. Each record has an immutable-looking demonstration ID for traceability, but this static site is not an evidence repository. Real audits require validated data provenance, approved sampling, professional judgment, and confidentiality safeguards.

Architecture: browser-based JavaScript control rules → structured evidence and exception results → constrained narrative template → human review. A future LLM integration would be limited to drafting from verified fields, with citations and explicit approval; no model or API key is connected here.
